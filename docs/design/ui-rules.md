# Steam Deck 大屏 UI 规则

本文件是 UI 的共享契约。QQ 与网易云页面可以有不同产品结构（[QQ](ui-qq.md) / [网易云](ui-ncm.md)），但必须共用这里的视觉、焦点、按键和宿主安全规则。实机效果以 [`assets/device-screenshots/`](../assets/device-screenshots/) 为准。

UI 分两个面，**职责严格分离**：右侧 QAM 面板做全局控制，大屏路由页做内容浏览。全部基于 Decky/Steam 的 `@decky/ui` 原语构建。两条硬约束，优先级明确：**① 绝不拖垮宿主 Steam UI（首要）；② 手柄可导航（Steam Deck 无鼠标）。**

## QAM 面板

插件在 Decky QAM tab 的内容（`src/QAM.tsx`），用 `PanelSection` / `PanelSectionRow` 承载，**只做全局控制，不含音乐内容**：

| 元素 | 组件 | 行为 |
| :--- | :--- | :--- |
| 选择音源 | `ButtonItem` | QQ 音乐 / 网易云音乐；`set_provider` 后通过 `src/providerChange.ts` 广播，已打开的大屏页随之切换。 |
| 登录与账号 | `ButtonItem` + 二维码 | QQ 可选 QQ / 微信扫码；账号页显示状态并提供退出、切换音源。 |
| 打开播放器 | `ButtonItem` | `Navigation.Navigate("/music")` 进大屏页。 |
| 音质上限 | `DropdownItem` | `set_quality`。 |
| 存储 | `ButtonItem` | 显示并清理缓存（日志目录）；清除数据需二次确认。 |
| 页脚 | `Footer` | 项目地址与版本号（`rollup.config.js` 从 `package.json` 注入）。 |

**未选音源是合法初始态**：QAM 显示音源选择、音质上限与存储管理；大屏页显示选择提示；左侧菜单不注入入口。

登录 UI 只维护 QAM 一份：大屏页需登录的整页内容用共享 `LoginGate` 引导一键拉开 QAM，login done 事件即时放行。

## 大屏路由页

- **路由注册**：插件加载时注册 `/music` 及详情、电台等独立路由，全部包 `Boundary`；`onDismount` 统一移除。路由 patch 进 gamepad 路由（`EUIMode.GamePad`，实证 `router-hook.tsx:81-83`）= 大屏全屏页。
- **进入**：QAM「打开播放器」或[左侧菜单注入](steam-menu-inject.md)。
- **详情页用独立路由**：页内子视图的 `onCancelButton` 拦不住系统返回，歌单、专辑、歌手、榜单详情都是独立路由，`B` 走原生返回。
- **按音源挂载**：`src/Page.tsx` 读当前音源挂 `QQApp` / `NCMApp`，订阅切源广播。

### 封面图

封面是二进制大块(每张几十 KB),**绝不走 bridge 的 NDJSON/callable 控制面**——一屏 50 张 base64 塞进 RPC 是灾难。取图三选一:

| 方案 | 怎么回事 | 取舍 |
|---|---|---|
| **A 直连 CDN(选它)** | provider 只回封面 **URL**;UI `<img src={封面URL}>` 由浏览器原生 GET + 缓存;队列浮层用 `onError` 显示占位,其余封面暂无显式错误占位 | 最简、图裂不崩溃;代价:静态图绕过 bridge |
| B decky `/fetch` 代理 | 走 Decky 自带 `/fetch` | 不直连但要处理 auth token |
| C 后端下载缓存 | provider/bridge 下到 `DECKY_PLUGIN_RUNTIME_DIR`,UI 读本地 | 最合红线但最重;Steam CEF 加载 `file://` 权限待验证 |

> **红线精确化**:"UI 所有消息经 bridge"的**本意是音乐控制/数据/音频不泄漏、可隔离**。封面是**静态展示资源**,非业务数据;`<img>` 拉图失败只图裂(队列浮层显示占位),**不威胁崩溃隔离**。故封面等静态图片**允许浏览器直取 CDN 封面**(方案 A),音乐控制/数据/音频仍必经 bridge。

## UI 崩溃隔离（首要约束）

**风险根源:我们是侵入式插件,前端与 Steam Gamepad UI 跑在同一 Chromium 上下文 / 同一 JS 堆 / 同一主线程(SharedJSContext)。** 后端多进程隔离救不了前端——前端天生同域。这是压倒一切的第一约束:宁可我们的 UI 自己不可用,也绝不能让 Steam 界面崩溃/冻结。

**Decky 已给的兜底(实证,必要但不充分):**

- 每条注入路由套 `<ErrorBoundary>`(`router-hook.tsx:294`),QAM 内容也套(`PluginView.tsx:41`)。**渲染期/生命周期**抛异常 → 显示 Decky 错误页,Steam 存活,可 `_deckyForceRerender` 恢复(`errorboundary-hook.tsx:104`)。
- 全局错误归因区分插件错误 vs Valve 错误(`getLikelyErrorSourceFromValveError`)。

**React ErrorBoundary 抓不到、必须我们自己防的逃逸路径:**

| # | 逃逸风险 | 后果 | 我们的规避(强制) |
|---|---|---|---|
| 1 | **异步/事件回调抛错**(`callable()` promise、`onClick`、`setTimeout`) | 逃逸边界→全局未处理拒绝 | 每个 `callable`、事件处理、promise **一律 try/catch**;失败落到 UI 内的错误态,不外抛 |
| 2 | **阻塞主线程**(同步死循环/重计算/超大同步解析) | **冻结整个 Steam UI**(单线程) | 前端**零重计算**:解码/拉流/加密全在后端进程(架构红利);UI 只做展示+IPC |
| 3 | **未清理副作用**(定时器、监听器、`addRoute` 未在卸载移除) | 跨插件 reload 在共享上下文累积泄漏 | 组件卸载/`_unload` 时清空所有 timer、`removeEventListener`、`removeRoute` |
| 4 | **篡改宿主**(monkey-patch Steam 内部 / 改全局原型 / 污染全局命名空间) | 破坏宿主状态 | **只用文档化的 `@decky/ui`+`@decky/api`**;绝不 patch Steam 内部,绝不写全局变量 |
| 5 | **无界渲染**(上万搜索结果/歌单节点灌进 Steam DOM) | 卡顿/内存膨胀 | 列表虚拟化/分页;搜索输入 debounce;绝不一次渲染巨量节点 |
| 6 | **IPC 永不返回**(后端 hung/崩溃,`callable` 不 resolve) | UI 永久挂起 | 所有 IPC 带**超时**;超时→graceful 状态,不空转 |
| 7 | **后端数据缺失/畸形**(后端是独立进程,可能崩) | 渲染期解引用 undefined 抛错 | **防御式渲染**:null-check、默认值;缺字段绝不在渲染期抛 |

**纵深防御:自套 ErrorBoundary。** 除 Decky 外层边界,我们在自己两个 UI 面(QAM、大屏页)顶层**各再套一层 `ErrorBoundary`**,子树出错时显示我们自己的降级 UI(“暂时不可用/重试”),连 Decky 兜底都尽量不触发。

**验收(每个 UI 改动的硬门槛):** 注入错误、杀死后端进程、灌畸形数据、断网——**Steam UI 始终不崩不冻**,最坏只是我们的面板显示错误态并可恢复。这是比功能更优先的验收项。

## 手柄实现约定

- **一切可交互元素包 `Focusable`**(实证遍布 `@decky/ui`):`onActivate` / `onOKButton`(A)/ `onCancelButton`(B,返回上一层或退出页)/ `onSecondaryButton`(X/Y)。
- **焦点走位**:方向键遍历焦点树;网格/横向布局用 `NavEntryPositionPreferences.MAINTAIN_X`(实证 `PluginCard.tsx:152`)保持列对齐,避免焦点乱跳。
- **搜索输入**:`TextField` 聚焦即唤起 Steam 手柄软键盘(实证 `Store.tsx` 搜索框),不依赖物理键盘。
- **上下文操作**:长列表项用 `showContextMenu` + `Menu`/`MenuItem`(实证 `plugin_list/index.tsx:63`),而非 hover 菜单。
- **禁止项**:无纯 hover 交互、无纯鼠标点击、无不可聚焦的可点区域;焦点环必须可见。
- 验收:**纯手柄从 QAM 选 provider → 进大屏 → 搜索 → 选歌 → 播放 → 控制,全程不接鼠标键盘可完成**。

## 目标

- 纯手柄可用：无鼠标、无触屏也能完成找歌、播放、控制、退出。
- 像 Steam 游戏模式页面：遵循官方库 / 商店的 10-foot UI 范式，不照搬手机 App。
- 不拖垮宿主：Steam UI 与插件前端在同一 Chromium 上下文，插件错误只能降级插件自身。

## 顶栏与布局

| 区域 | 规则 |
| :--- | :--- |
| SteamOS 全局 chrome | 右上角搜索、通知、Wi-Fi、电量、时间、头像属于系统；插件不绘制、不聚焦、不修改。 |
| 插件内容首行 | 品牌色音乐图标与 provider 名称、顶层 Tab、`L1/R1` 提示和当前播放状态徽章放在内容区首行。 |
| 顶层导航 | 使用横向 Tabs；`L1/R1` 循环切换 provider 页面。 |
| 个人资产页 | 遵循官方库页面：全宽二级 Tab 行 + 全宽列表 / 网格；不要常驻左侧栏。 |
| 内容区 | 主内容占满宽度；推荐页可用横向条带 / 网格，搜索页可用列表 + 热搜侧栏。 |

## 去常驻播放条

大屏 UI 不保留底部固定 MiniPlayer。

原因：SteamOS 软键盘弹出时会压缩整个 CEF WebView 高度。任何 `position: fixed; bottom: 0` 或 flex 底部常驻栏都会被顶到键盘上方，挤压搜索结果并破坏官方 UI 习惯。

替代机制：

1. **Tab 状态徽章**：顶层 Tab 行最右侧显示小封面 + EQ 播放态，不显示歌名；纯展示，不进焦点树。
2. **`Start` 盲操**：任何页面、任何焦点位置都可播放 / 暂停；队列空或后端不可用时不显示可执行提示。
3. **`Y` 队列浮层**：普通页面按 `Y` 打开右侧临时模态面板；浮层关闭后恢复原焦点。
4. **沉浸播放页**：完整进度、音量、上一首 / 下一首、歌词和评论收归 `Now Playing`；provider 专属电台页只保留红心、播放 / 暂停、下一首(或垃圾桶)。

## 视觉规则

| 项 | 规则 |
| :--- | :--- |
| 背景 | 近黑背景，允许封面模糊光晕；不要大面积品牌色铺底。 |
| 卡片 | 封面图本身就是卡片；直角或 2-4px 小圆角；不要手机式大圆角容器。 |
| 焦点态 | 2-3px 细白描边贴近元素边缘，允许轻微外发光和缩放。 |
| 列表选中 | 水平灰色渐变高亮条；必要时用 Steam 蓝左侧指示条。 |
| 品牌色 | Steam 蓝 `#1a9fff` 是主交互色；QQ 绿 / NCM 红只做 Logo、徽标、红心等点缀。 |
| 字体和层级 | 标题粗体，正文常规；小节标题可用全大写小字号灰色。 |
| Footer Legend | 底部图例条由系统渲染。插件只提供当前焦点可执行动作的文案，不自绘样式。 |

队列浮层与页面共用近黑背景、4px 小圆角、歌曲信息层级。轻遮罩保留页面上下文；
只在该模态实例内覆盖 Decky 默认对话框外观，不修改 Steam 全局样式。
当前曲的蓝色标记与白色手柄焦点分开表达；电台当前曲只读，禁止无操作的 A/X 图例。
标题与关闭入口固定，列表区域独立滚动；完整队列可导航，DOM 只保留可见窗口及 overscan。

## 歌词定位与跟随

- 进入“正在播放”或从热评返回歌词时，按当前播放时间选择歌词行，在首次可见绘制前直接定位。
- 歌词仍在加载、没有当前行或容器尚无有效高度时，不标记为已完成首次定位；歌词就绪后再定位。
- 已显示歌词的后续换句保持平滑跟随；不恢复离开 Tab 时的旧滚动位置。
- 手动浏览的 4 秒静默期内不抢滚动，之后随换句恢复跟随。只滚动歌词容器，不使用会拖动外层页面的 `scrollIntoView`。
- 不为此常驻隐藏页面或增加轮询。无初始滚动动画必须用连续画面和位置采样验收，静态截图只记录视觉状态。

## 焦点模型

```text
主内容焦点树：Tabs 下的搜索、列表、网格、歌词、沉浸页控制
        |
        | Y / X / A 触发
        v
模态浮层焦点树：队列、上下文菜单、确认框
```

硬规则：

- 所有可交互元素必须能被 `Focusable` 选中。
- 禁止 hover-only、touch-only、不可见点击热区。
- 网格和多列布局使用 `MAINTAIN_X`，避免上下移动时列错位。
- 搜索框聚焦后按 `A` 必须唤起 Steam 软键盘。
- 长列表滚近底部自动翻页并窗口化渲染；不能一次性把大量节点塞进 DOM。
- 滑块聚焦后十字键左右微调（`onGamepadDirection` 消费 LEFT/RIGHT，UP/DOWN 放行离开）；进度条停手后才提交 seek，语义见[性能](performance.md)。
- 模态浮层关闭后恢复触发前焦点；原节点卸载时回退到当前页面第一个主要交互元素。

## 按键契约

| 按键 | 行为 |
| :--- | :--- |
| D-Pad / 左摇杆 | 焦点导航；在歌词区上下手动滚动；在滑块上左右微调。 |
| A | 确认：播放、进入详情、在搜索框唤起软键盘。 |
| B | 路由原生返回；关闭模态浮层。路由返回不可拦截，因此不用它恢复歌词跟随。 |
| X | 上下文菜单；在 NCM 歌词页切换歌词 / 热评；在电台页可覆盖为垃圾桶 / 下一首。 |
| Y | 普通页面打开播放队列；在电台页可覆盖为红心等局部快捷键。 |
| Start | 全局播放 / 暂停；不依赖当前焦点。 |
| View | 未绑定；只有验证到真实收益后再绑定。 |
| L1 / R1 | 顶层页面切换。 |
| L2 / R2 | 二级 Tab 循环切换（资产页、搜索分类）。 |
| Steam / QAM | 系统保留键，插件不绑定。 |

## Footer Legend 规则

- 通过 `Focusable` 的 `actionDescriptionMap`、`onOKActionDescription` 等属性声明文案。
- 图例随焦点变化；根级 `Focusable` 可提供全局默认，子元素同按键文案会覆盖父级。
- 左侧 `STEAM` 菜单、白圈图标、排列和位置由系统控制，插件不得自绘仿冒。
- 不可用动作必须隐藏或置灰。`X` / `Y` 在特殊模式下被覆盖时，提示文案必须同步改成真实语义。

## 宿主安全

这些是上文「UI 崩溃隔离」在页面层的落点：

- 所有 RPC、事件处理、计时器回调都要捕获错误，不把异常抛到全局。
- 后端死亡、断网、畸形数据只能渲染错误态，不能冻结 Steam UI。
- 图片用 CDN 封面 URL；队列浮层失败显示占位图，其余封面破图不影响宿主。
- 不 monkey-patch Steam 全局对象，不写全局命名空间。
- 组件卸载时清理监听器、计时器、路由和模态浮层。

## 验收

每个 provider 页面都必须能用实体按键完成：

1. 进入 `/music`。
2. 切换顶层页面和二级 Tab。
3. 搜索或打开推荐内容。
4. 选歌播放。
5. 暂停 / 继续。
6. 打开并关闭队列浮层。
7. 打开并关闭上下文菜单。
8. 在歌词 / 评论区域手动浏览并恢复自动跟随。
9. 在后端异常、断网或畸形数据时显示可恢复错误态。
